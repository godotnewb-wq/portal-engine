# engine/state

The game state and what is saved: the player, time, the dice's state, each character's meters toward the player, relations between characters (with their relationship tags and note), what the player is to each character (`playerTies`), the party (Major Characters with the player; separate from tier), memories, learned facts, and a scene in progress (its turns, beats, checks, reading checks that succeeded, felt moods as feelings in the ruleset's words, comfort, expressions, departures). Saves are version 8 since milestone 4b (memories with ids, levels, revisits and a fading clock: the Memory Bank; a learned secret's fact id and codex pointer on its memory; `secretActivity` for dormancy; `Turn.exposed` for secrets that came out on screen). Also since 4b: aftermath and feelings toward a person (`aftermath`), ended feelings for the repeat rule (`endedFeelings`) and when each character last shared a scene with the player (`lastSeen`); `days.ts` reads days from the game clock (`dayOf`, from the ruleset's `clock.morning`; `daysSince`, in calendar days; `nextMorning`; `intensityOn`), words what someone carries (`carrying`, `aftermathWords`, `absenceWords`) and picks a scene's opening mood (`openingMood`: the strongest active aftermath or feeling toward someone in the scene, one toward someone present winning a tie, else the card's default). Comfort starts afresh each scene. Since milestone 4c the scene also keeps each witness's relationship answers between the two halves of its end (`scene.judged`, optional, so the save version is unchanged), a tie change keeps the line that showed it (`TieChange.line`, `TieEvent.line`), and a tag that begins in a group the ruleset marks `oneAtATime` ends the one held there. `ties.ts` (milestone 4b; relationships §3): tie changes (`tagNamed`, `tagsToward`, `needsAgreement`, `tieProblem`, `applyTie`, `answerTie`, `tieWords`, `tieQuestion`); the scene keeps pending changes, the player's answers and the changes made (`pendingTies`, `answered`, `tieEvents`). Also the save file format and slots.

**Public API** (`@engine/state`): `GameStateSchema`, `SceneSchema`, `TurnSchema`, `BeatSchema`, `MemorySchema`, `RelationSchema`; `createInitialState`, `startScene` (takes the scene's id; turns are numbered from it, and each turn keeps its id and the log session that recorded it), `stateProblems` (does a saved game still fit this pack?); `SaveFileSchema` (records the pack id and version), `SAVE_VERSION` (a save in an earlier format is refused with its own message and listed as `outdated`), slot ids, `latestSave`.

Scene *data* lives here, below the scene pipeline, so the two don't import each other.

**Depends on:** core, characters, pack.
